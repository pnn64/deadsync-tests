# Dyscontrolled Galaxy native rendering references

These compressed JSON files contain observations from ITGmania's renderer, not
transforms generated by DeadSync. They are used by the Dyscontrolled Galaxy
regressions in `crates/deadsync-shell/src/gameplay_regression_tests.rs`.

| Reference | Native session | Recorded drawing interval |
| --- | --- | --- |
| `dyscontrolled-pad-native.json.zst` | P1, Cel, M690, -10% Mini | Beats 33-44, including the platform |
| `dyscontrolled-post-pad-native.json.zst` | Versus, both players, Cel, M690, -10% Mini | Beats 43-104, including the transition and stars |
| `dyscontrolled-post-pad-single-native.json.zst` | P1, Cel, M690, -10% Mini | Beats 43-104, including the single-player stars |
| `dyscontrolled-ending-native.json.zst` | Versus, both players, Cel, M690, -10% Mini | Beats 284-345, including the orbit, outward split, and outro |

The capture uses harness version 0.1.110 and the clean ITGmania source revision
`663525dcb86eb570d0ef6a2e209678436660ae26`. The simfile SHA-256 is
`124827effe483710bc2f8965b002155d12c414d27bcb0e38fb34f02332945e9f`.
Each document retains executable, observer, source, raw-trace, and input
provenance. The original chart and its scripts are unchanged.

The native session uses OpenGL at 854 by 480, music rate 1, ITG sync offsets,
global offset -0.008 seconds, and zero visual delay. FastNoteRendering is
explicitly enabled and its effective value is checked at the start and end.
This preference matters: genuine note Models keep their depth between draws
when it is enabled. A capture with the preference disabled can conceal a
platform overlap defect.

The references include raw and visible song positions, screen update deltas,
independent song/player option approach deltas,
independent receptor draw visits, original mesh vertices, clip-space bases,
native draw sequence, and Model render state. Render-state protocol 1 records
the effective color, material, blend, depth, culling, and texture stages at the
native compiled-mesh submission. The harness exercises the observer with
independent fading, zero-alpha, diffuse/glow, and blend controls. Script errors
and dropped observation counters must be empty/zero.

The post-pad test compares both Cel meshes and preserves repeated submissions,
including overlapping players and separate diffuse/glow passes. Its fixed
probes cover integer and fractional beats, and it retains every observed frame
around Mini's brief collapse near beat 64. Receptor visits establish that a
frame was drawn even when native submits no taps. The test compares full XYZ
clip bases and W, visible projected positions, effective tint, texture,
depth/cull/blend state, and the order of mesh passes within each note.

The pad test uses ordinary Baked playback. It compares deduplicated projected
tap origins, receptor placement, and native draw order; its optional GPU check
requires visible tap pixels over the platform. The full basis and material
comparison described above applies to the post-pad references.

## What a passing comparison establishes

The strict post-pad comparison supplies native **clock inputs** to DeadSync's
Lua compiler and normal gameplay update path. It does not supply native actor
poses, modifier values, or expected geometry to the implementation. Player and
NoteField actors use screen deltas; Foreground actors use elapsed music time,
matching the separate native update paths. Default/Game arrow-effect timers
receive the recorded process elapsed time instead of the fixture renderer's
usual fixed clock. This matters for Drunk, which depends on application time
independently of song position. The recorded timestamp precedes native drawing;
it is not an observation of each individual ArrowEffects timer read.

Native `ModsGroup::Update` samples a separate timer before approaching current
options. The compiler receives the recorded SongOptions/P1/P2 timer deltas when
sampling Current speeds. The gameplay test also supplies each recorded player
option delta through a one-shot test-support input for its other approached
modifiers; these inputs do not replace the screen, audio, or gameplay clock.
Missing option-clock observations are rejected rather than replaced with the
screen delta. This distinguishes small material-color differences caused by
clock inputs from rendering arithmetic.

At the probes after beat 102.01, the chart also applies random TopScreen shake.
The reference does not retain those random samples. The comparison permits only
one XY translation shared by every mesh in that frame, bounded by the chart's
30-pixel magnitude per draw and projected through Player's native camera.
Relative note positions, all XYZ bases, Z/W, submission counts, material state,
and mesh/pass order within each note remain strict. This bounded comparison
cannot distinguish a deterministic common XY offset inside the shake envelope;
it is not an exact absolute-position check for those frames. Independent
negative controls reject a changed basis, an individually misplaced mesh,
a missing mesh, and changed depth.

The capture is not a pixel oracle. It does not establish exact random-shake
samples, mesh-index/topology, texture-coordinate, filter, shader, cross-note
compositing, or whole-chart parity. The chart also
contains frame-dependent callbacks: its recurring `sleep(0.02)` update samples
beat and accumulates rotation. Ordinary Baked compilation samples at 60 Hz and
can therefore follow a different trajectory from native playback at another
cadence. Matching a captured input schedule does not prove that those ordinary
Baked trajectories are identical.

Optional GPU checks render both the captured-clock replay and ordinary Baked
playback. They verify that taps produce visible pixels, including over the
platform, and retain a native empty interval as a negative control. These are
visibility checks, not a claim of image equality. The fixture does not advance
background video, so its stars-section screenshots use the static background.
Native single-player stars
also contain sparse or empty intervals; the fuller stream requires the
authored second-player contribution.

## Targeted speed and movie controls

The adjacent `speed-mode-approach-input.json` is executed by the harness's
native `option_control` oracle. Its result in `speed-mode-approach-native.json`
retains the pinned source provenance. The native assertions show that parsing
`clearall` followed by `*2 2x` leaves Current's MaxScrollBPM approaching zero at
one BPM per second: M690 remains M680 after ten seconds, although ScrollSpeed
has already reached 2. `ArrowEffects.cpp` gives the nonzero maximum BPM
precedence. A direct `XMod(value, approach)` setter changes the approach rate
of all four speed fields instead. `captured_speed_modes.rs` checks that the
ordinary compiler carries those Current values into gameplay windows.

`sprite-movie-clock-native.json` records calls made by the pinned native
`Sprite::Update` to a recording movie texture. It covers pause/resume, the
first-update skip, decode control, visibility, effect-clock deltas, seek,
playback rate, looping, parent update rate, parent and Sprite hibernation,
and queued animation commands. The texture recorder does not decode a movie
or infer frame timestamps. DeadSync's movie tests use those native calls to
check its retained clock, then separately check baked media sampling. This
controls the `dg.mpg` text sequence, which the chart pauses until `ShowDG`
at beat 67, independently of whole-song elapsed time.

The Player discontinuity regression in `captured_player_steps.rs` covers the
post-pad alternating rotation and the later DYSCONTROLLED depth/zoom flips.
Native setters change the current pose immediately when no tween is queued;
baked playback must hold that pose until the next callback instead of
interpolating toward an unexecuted flip. Timed tweens and setters that retarget
a pending tween retain continuous motion. This does not remove the different
callback-cadence limitation described above.

The ending reference retains all 13,885 native updates from preroll through
beat 345.020782, with geometry recording starting at beat 284. It contains
2,405 drawn frames, 67,988 Model submissions, and 19,240 receptor visits, with
both players observed and no script errors or dropped records. The full JSON
SHA-256 is `d43b19be4cc5260e62785130e1d561b1a5b555ffda2b19286953c464ebacf433`;
the compressed reference SHA-256 is
`3eebb9f491333b48124b2005909ddf3bccc8713a7e93b844641415baa213e8dd`.
The capture uses the same pinned native source and unchanged committed chart,
with `--style versus --drawable-from-beat 284 --until-beat 345 --capture-fps 120
--timeout 240`, and no fixed update delta. Geometry recording starts late;
native playback and the retained independent clocks still begin at preroll.

The ending observer also records native ArrowEffects cache clocks for 13,884
updates, including every active-song update, and current Player X/Y/Z for both
players on all 2,405 drawn frames. Cache observations attach to their exact
native update frame. The raw double-precision Tipsy timer is supplied only to
the corresponding player's Tipsy computation; the general arrow-effect clock
remains independent. These are cache inputs, not per-query draw timer reads.
The recorded Tipsy clocks remain at their last earlier use during this ending;
no TanTipsy clock was observed. Current Player positions are expected outputs
only and are never injected into DeadSync. Native GetZoom reads the destination
tween state, so it is deliberately excluded from the current-position record.

Those same drawn frames retain 4,810 Player Current-option observations: native
Tilt, Skew, Mini, Brake, Drunk, and Tipsy, plus their raw getter approach-speed
members and the nullable Hallway/Distant/Incoming/Space getters. These Current
values are expected outputs, never replay inputs. Current's getter speed is
not the destination layer's approach setting. Canonical Tilt and Skew are read
directly, without inferring them from a possibly absent perspective alias.

The ending's `dys_rotamp` upvalue refers to an unnamed `Def.Actor`, which
starts a two-beat tween from X=0 to X=180 at beat 286. Native `Actor::GetX`
reads the current tweened position, and `ActorFrame::UpdateInternal` updates
this sibling before the chart's recurring callback reads it. A control actor
omitted from baked render rows must therefore retain native queue/getter
ownership when its late tween starts. It must not keep stale preparation
getters that require a sampled render row to advance.

Native `Actor::UpdateTweening` removes completed tweens before later setters
write the current pose. Sampled Player preparation retains physical queue
entries after their scheduled motion ends, so those entries cannot decide
whether a later X/Y setter is immediate. The active sampled schedule preserves
continuous retargeting while a tween is pending; after completion, the ending's
alternating positions must remain steps instead of blending toward each other.

An immediate reset to the preparation baseline must also publish a constant
window after holding the previous step. Omitting that reset would extend the
old value indefinitely in gameplay. The controls exercise position and zoom
resets, helper-driven zoom pulses, and a reset on the last sampled update;
untouched baseline transforms still publish no windows.

Native PlayerOptions approaches PerspectiveTilt and Skew independently at their
authored speeds. Hallway, Distant, Space, Incoming, and Overhead set both targets
and both speeds. The ending's short Hallway pulse therefore retains nonzero
Current tilt after its reset starts. The gameplay controls cover finite and
zero speeds, alias targets, independent players, profile baselines, direct Lua
samples, and the idle update path. This retained Current tilt also controls
the native note visibility range and Brake's effect height.

Native Player positioning also extrapolates Tilt beyond 100% and applies its
zoom correction uniformly to X/Y/Z. The ending reaches almost 200% Tilt and
later Space above 100%; clamping the camera loses those authored angles.
Omitting the tilt zoom on Z changes both Bumpy displacement and model depth.
The camera controls cover both signs of 200% Tilt, both Reverse states, and
all three basis vectors with fixed native numeric expectations.

The ordinary Baked ending test checks consumed gameplay Player X at beats
294, 302, and 315, accepting the chart's two flicker phases and bounded 60 Hz
callback quantization. It also checks the explicit left/right split after
beat 320. The native ending test uses the recorded clock schedule and the same
full geometry/material comparison as the post-pad tests. At its 21 selected
frames it also compares consumed Player X/Y/Z with the native current position
within 0.01 pixels and the six Current-option values within 0.0001. Its post-320 probes
avoid active gunfire shake, so no additional random-translation tolerance is
used. The chart deliberately crosses the fields during parts of the orbit and
converges them again for the outro; those authored overlaps remain valid.

`captured_hud_transforms.rs` checks the ordered Judgment/Combo wrappers and
resolved child pose. Native `Player::Update` replaces the child's destination
after its subtree advances and before the song callback, while preserving
wrappers and base scale. Rendering applies that complete chain once, including
the native Mini/Tiny scale. Untouched HUD actors keep the theme's profile-based
placement; a wrapper or authored transform setter opts the actor into captured
placement. The live control also checks that publishing the pose does not
restore stale compiler-preparation state.

The shell's system-overlay regression covers the Autoplay indicator. Native
`ScreenManager` draws `ScreenSyncOverlay` separately from the gameplay screen.
Song-controlled gameplay overlay visibility and tint therefore do not suppress
or recolor the system indicator; the user's gameplay HUD visibility still
applies.

From the DeadSync root, run the pad and post-pad tests in separate processes
when requesting GPU captures, because the window backend permits one event
loop per process. On Windows, set `DEADSYNC_DYSCONTROLLED_CAPTURE_DIR` to an output
directory to enable the optional screenshots. These GPU capture paths are
currently compiled only on Windows.

```text
cargo test --locked -p deadsync-shell --lib dyscontrolled_pad_matches_native_geometry_and_draw_order -- --nocapture --test-threads=1
cargo test --locked -p deadsync-shell --lib dyscontrolled_post_pad_matches_native_two_player_taps -- --nocapture --test-threads=1
cargo test --locked -p deadsync-shell --lib dyscontrolled_post_pad_matches_native_single_player_taps -- --nocapture --test-threads=1
cargo test --locked -j 1 -p deadsync-shell --lib dyscontrolled_ending -- --nocapture --test-threads=1
cargo test --locked -j 1 -p deadsync-song-lua --features test-support --test captured_player_steps -- --test-threads=1
```
