# Dyscontrolled Galaxy native rendering references

These compressed JSON files contain observations from ITGmania's renderer, not
transforms generated by DeadSync. They are used by the Dyscontrolled Galaxy
regressions in `crates/deadsync-shell/src/gameplay_regression_tests.rs`.

| Reference | Native session | Recorded drawing interval |
| --- | --- | --- |
| `dyscontrolled-pad-native.json.zst` | P1, Cel, M690, -10% Mini | Beats 33-44, including the platform |
| `dyscontrolled-post-pad-native.json.zst` | Versus, both players, Cel, M690, -10% Mini | Beats 43-104, including the transition and stars |
| `dyscontrolled-post-pad-single-native.json.zst` | P1, Cel, M690, -10% Mini | Beats 43-104, including the single-player stars |

The capture uses harness version 0.1.110 and the clean ITGmania source revision
`663525dcb86eb570d0ef6a2e209678436660ae26`. The simfile SHA-256 is
`124827effe483710bc2f8965b002155d12c414d27bcb0e38fb34f02332945e9f`.
Each document retains executable, observer, source, raw-trace, and input
provenance. The original chart and its scripts are unchanged.

The native session uses OpenGL at 854 by 480, music rate 1, ITG sync offsets,
global offset -0.008 seconds, and zero visual delay. FastNoteRendering is
explicitly enabled and its effective value is checked at the start and end.
This preference matters: genuine note Models keep their depth between draws
when it is enabled. A capture with the preference disabled can conceal a
platform overlap defect.

The references include raw and visible song positions, screen update deltas,
independent song/player option approach deltas,
independent receptor draw visits, original mesh vertices, clip-space bases,
native draw sequence, and Model render state. Render-state protocol 1 records
the effective color, material, blend, depth, culling, and texture stages at the
native compiled-mesh submission. The harness exercises the observer with
independent fading, zero-alpha, diffuse/glow, and blend controls. Script errors
and dropped observation counters must be empty/zero.

The post-pad test compares both Cel meshes and preserves repeated submissions,
including overlapping players and separate diffuse/glow passes. Its fixed
probes cover integer and fractional beats, and it retains every observed frame
around Mini's brief collapse near beat 64. Receptor visits establish that a
frame was drawn even when native submits no taps. The test compares full XYZ
clip bases and W, visible projected positions, effective tint, texture,
depth/cull/blend state, and the order of mesh passes within each note.

The pad test uses ordinary Baked playback. It compares deduplicated projected
tap origins, receptor placement, and native draw order; its optional GPU check
requires visible tap pixels over the platform. The full basis and material
comparison described above applies to the post-pad references.

## What a passing comparison establishes

The strict post-pad comparison supplies native **clock inputs** to DeadSync's
Lua compiler and normal gameplay update path. It does not supply native actor
poses, modifier values, or expected geometry to the implementation. Player and
NoteField actors use screen deltas; Foreground actors use elapsed music time,
matching the separate native update paths. Default/Game arrow-effect timers
receive the recorded process elapsed time instead of the fixture renderer's
usual fixed clock. This matters for Drunk, which depends on application time
independently of song position. The recorded timestamp precedes native drawing;
it is not an observation of each individual ArrowEffects timer read.

Native `ModsGroup::Update` samples a separate timer before approaching current
options. The test supplies each recorded player option delta through a one-shot
test-support input; it does not replace the screen, audio, or gameplay clock.
Missing option-clock observations are rejected rather than replaced with the
screen delta. This distinguishes small material-color differences caused by
clock inputs from rendering arithmetic.

At the probes after beat 102.01, the chart also applies random TopScreen shake.
The reference does not retain those random samples. The comparison permits only
one XY translation shared by every mesh in that frame, bounded by the chart's
30-pixel magnitude per draw and projected through Player's native camera.
Relative note positions, all XYZ bases, Z/W, submission counts, material state,
and mesh/pass order within each note remain strict. This bounded comparison
cannot distinguish a deterministic common XY offset inside the shake envelope;
it is not an exact absolute-position check for those frames. Independent
negative controls reject a changed basis, an individually misplaced mesh,
a missing mesh, and changed depth.

The capture is not a pixel oracle. It does not establish exact random-shake
samples, mesh-index/topology, texture-coordinate, filter, shader, cross-note
compositing, or whole-chart parity. The chart also
contains frame-dependent callbacks: its recurring `sleep(0.02)` update samples
beat and accumulates rotation. Ordinary Baked compilation samples at 60 Hz and
can therefore follow a different trajectory from native playback at another
cadence. Matching a captured input schedule does not prove that those ordinary
Baked trajectories are identical.

Optional GPU checks render both the captured-clock replay and ordinary Baked
playback. They verify that taps produce visible pixels, including over the
platform, and retain a native empty interval as a negative control. These are
visibility checks, not a claim of image equality. The fixture does not advance
background video, so its stars-section screenshots use the static background.
Native single-player stars
also contain sparse or empty intervals; the fuller stream requires the
authored second-player contribution.

From the DeadSync root, run the pad and post-pad tests in separate processes
when requesting GPU captures, because the window backend permits one event
loop per process. On Windows, set `DEADSYNC_DYSCONTROLLED_CAPTURE_DIR` to an output
directory to enable the optional screenshots. These GPU capture paths are
currently compiled only on Windows.

```text
cargo test --locked -p deadsync-shell --lib dyscontrolled_pad_matches_native_geometry_and_draw_order -- --nocapture --test-threads=1
cargo test --locked -p deadsync-shell --lib dyscontrolled_post_pad_matches_native_two_player_taps -- --nocapture --test-threads=1
cargo test --locked -p deadsync-shell --lib dyscontrolled_post_pad_matches_native_single_player_taps -- --nocapture --test-threads=1
```
